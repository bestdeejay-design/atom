Это **точная копия (форк) официального редактора Atom** в его финальном состоянии.

|---|---|

| Electron | `11.5.0` (Chromium 87, вышел в ноябре 2020) |

| CI | отсутствует (в `.github/` только боты lock/stale) |

> ⚠️ Важно понимать: это **не «редактор для macOS»**, а кроссплатформенный редактор.
> macOS-специфичного кода в нём относительно немного (`resources/mac/`,
> `.icns`-иконки, `Info.plist`, работа с меню и подписью). Собирать его под Mac
> можно, но это полноценный Electron-проект, а не нативное macOS-приложение.

### Из чего состоит «сам редактор»

В `package.json` — **157 зависимостей**:

| Источник | Кол-во | Примеры |
|---|---|---|
| `git+https://github.com/atom/*` | **67** | `tree-view`, `settings-view`, `find-and-replace`, `tabs`, `github`, все `language-*` |
| локально в `packages/` | 27 | темы `one-dark-ui`, `atom-dark-syntax`, `welcome`, `git-diff` |

То есть **большая часть привычного интерфейса (дерево файлов, настройки, поиск,
табы, автодополнение, все подсветки синтаксиса) лежит не в этом репозитории**,
а подтягивается из отдельных репозиториев в архивированной организации `atom`.
Проверено: они **всё ещё доступны и скачиваются** (GitHub не удалил архивы).

## 3. Как он собирается

Цепочка (`script/bootstrap` → `script/build`):

1. **Проверка окружения** (`script/lib/verify-machine-requirements.js`):
   - Node.js **≥ 10.12** (в CI использовался **12.16.3**)
   - Python **2.6 / 2.7 / 3.5+** — для `node-gyp`
2. **Bootstrap**: установка `script/`, `apm/`, 157 пакетов, из них часть —
   **нативные модули, компилируемые из исходников**:
   `@atom/watcher`, `@atom/nsfw`, `git-utils`, `superstring`, `pathwatcher`,
   `tree-sitter` (форк DeeDeeG), `vscode-ripgrep`, `spellchecker`, `@atom/fuzzy-native`
3. **Транспиляция**: CoffeeScript → JS, Babel, CSON → JSON, PEG.js
4. **`electron-packager`** — сборка `.app` (скачивает бинарник Electron 11.5.0)
5. **`mksnapshot`** — генерация V8-снапшота для быстрого старта
   ⚠️ самый хрупкий шаг, часто ломается на новых Xcode
6. **Подпись/нотаризация** — опционально (`--code-sign`), требует сертификат Apple Developer

Итог: `out/Atom.app` (плюс `out/atom-mac.zip` при `--compress-artifacts`).

## 5. Главный технический барьер: Apple Silicon

Если у тебя MacBook на чипе M-серии (M1/M2/M3/M4), вот что стоит между тобой и сборкой:

**a) Архитектура захардкожена под Intel**
```js
// script/lib/package-application.js
arch: process.platform === 'darwin' ? 'x64' : HOST_ARCH, // OS X is 64-bit only
```
→ получится **x64-сборка**, которая на M1/M2/M3 работает только через **Rosetta 2**.

**b) Снапшот тоже жёстко x86_64**
```js
// script/lib/generate-startup-snapshot.js
// TODO: check if we're building for arm64 and use the arm64 version of the binary
destinationPath = path.join(startupBlobDestinationPath, 'v8_context_snapshot.x86_64.bin');
```
→ в коде прямо оставлен TODO про arm64. Значит, авторы понимали проблему, но не доделали.

**c) Нативные модули** — `@atom/watcher`, `@atom/nsfw`, `git-utils`, `superstring`
версий 2020-2022 годов. Под arm64 их придётся пересобирать; часть может не собраться
современным clang из Xcode 16/17.

**Хорошая новость:** Electron 11.5.0 **умеет** `darwin-arm64` — то есть нативная
arm64-сборка технически возможна. Это не «переписать проект», а починить
сборочные скрипты + разобраться с нативными модулями.

## 6. Что реально можно сделать — варианты

### Вариант A. «Просто получить рабочий Atom на MacBook» (быстро)
Собрать как есть, x64, запуск через Rosetta 2.
- ✅ Реально за 1 сессию, риск низкий
- ✅ Есть готовый документированный путь (`script/bootstrap`, `script/build`)
- ⚠️ Rosetta 2: Apple уже заявляла, что после macOS 27 её роль будет урезана
- ⚠️ Тяжелее по батарее на M-чипах
- ❌ Пакеты ставить нельзя (реестр мёртв)

### Вариант B. «Привести репозиторий в порядок» (гигиена проекта) ⭐ рекомендую начать с этого
Не трогая логику редактора:
1. **`.nvmrc`** — зафиксировать Node 12.16.3 (на Node 22 сборка не пойдёт)
2. **README на русском** — что это, как собрать, что не работает и почему
3. **GitHub Actions CI** — заменить мёртвый Azure Pipelines на современный workflow
   (`macos-15-intel` — бесплатный macOS-раннер для публичных репо!)
   → это даёт возможность **собирать `.app` в облаке GitHub и скачивать артефакт**,
   не мучая свой ноутбук окружением сборки
4. **Отключить мёртвые сервисы** — автообновление, краш-репортер, телеметрию
   (иначе редактор будет стучаться в никуда при каждом запуске)
5. **Плашка про реестр** — чтобы установка пакетов не выглядела сломанной без объяснений
6. **Чистка мёртвого CI** — `script/vsts/` (Azure) убрать или пометить
7. **Локализация/пометки** — где и что правилось

### Вариант C. «Нативная сборка под Apple Silicon»
Патчи `package-application.js` (arch arm64), `generate-startup-snapshot.js`
(выбор `v8_context_snapshot.arm64.bin`), пересборка нативных модулей.
- ✅ Настоящий editor «под свой Mac», без Rosetta
- ⚠️ Средний/высокий риск: нативные модули 2020-х под arm64
- ⚠️ Нужен реальный Mac для проверки (в песочнице macOS нет)

### Вариант D. «Модернизация кода: Electron 11 → 30+»
Переход на современный Node/Chromium (как Pulsar).
- ❌ **Очень большой объём**: выпилен модуль `remote`, десятки сломанных API,
  перегенерация снапшотов, пересборка всех нативных модулей, переписывание
  CoffeeScript-файлов, обновление ~157 зависимостей
- ℹ️ Команда Pulsar делала это **несколько лет** и продолжает делать
- ➡️ Реалистично только как «долгий хобби-проект», не как способ получить редактор

### Вариант E. «Просто взять Pulsar»
Честный вариант, который надо назвать:
- **Pulsar** (`pulsar-edit/pulsar`) — форк Atom, живой: версия **1.132.1** (май 2026),
  **Electron 30**, Node 20, есть **готовые сборки под Apple Silicon**
  (плюс в 1.132.0 добавили встроенный терминал)
- Пакеты из мёртвого реестра atom.io они перенесли на свой живой реестр
- ➡️ Если цель — **работать в редакторе сегодня**, это ответ.
  А этот репозиторий тогда — площадка для экспериментов и «своего» форка.

1. **Какой у тебя Mac** — Intel или Apple Silicon? Это определяет этапы 3-4.
2. **Какая версия macOS** — Electron 11 (2020) может вести себя капризно на macOS 26.
3. **Цель**: «работать в редакторе» или «чинить и развивать свой форк»?
4. **Что именно ты знаешь про недостатки** этого редактора — какие болячки
   мешают лично тебе? Это определит, что чинить в первую очередь.

## 9. Полезные факты для справки

- Сборка из исходников **не требует** сертификатов Apple — подпись опциональна
- Локально собранный `.app` не имеет карантина Gatekeeper (в отличие от скачанного)
- Публичные репозитории на GitHub получают **бесплатные macOS-раннеры**
  (`macos-15-intel` — Intel x64, `macos-14/15/26` — arm64)
- Полная сборка Atom тяжёлая: bootstrap скачивает ~1 ГБ зависимостей и
  компилирует нативные модули — на CI это десятки минут
- Файл `script/deprecated-packages.json` — просто база устаревших пакетов,
  к сборке отношения не имеет, но полезен как история экосистемы
