## Правила проекта

1. **Вся работа — в ветке текущей сессии.** Никаких побочных веток.
2. **Мерж в `master`** делаем через Pull Request по команде владельца, когда этап готов.
3. **После каждой волны** этот документ обновляется: статус, журнал, следующие шаги.
4. **Коммиты пишутся по-русски**, с префиксами `feat(lite)` / `lite` / `build` / `ci` / `docs` / `fix`.

## Цель проекта

Превратить форк финального Atom в **лёгкий, автономный, офлайн-редактор для
Apple Silicon Mac**, стилизованный в духе серии Dajet.

Три опоры:
1. **Автономность** — ноль обращений в сеть. ✅ сделано
2. **Вес** — минимум лишнего кода, нативный arm64 без Rosetta (598 → 429.2 МБ, архив 178.5 → 144.0 МБ, установка −72 МБ). ✅ сделано
3. **Стиль** — две пары тем: `dajet` (светлая стеклянная + тёмная матовая + как в системе, терракотовый акцент) и `joer` (пять атмосфер: `lounge`, `club`, `romantic`, `space`, `velvet`). ✅ сделано

### Волна 0 — Аудит (`48522be`)

Изучен репозиторий: `docs/AUDIT-RU.md`.

**Главные находки:**
- Это точная копия `atom/atom` @ `1c3bd35` (22.11.2022), ноль своих коммитов
- Реестр пакетов `atom.io` мёртв — GitHub официально это подтвердил

Отдельно проверил конкурента — **Pulsar** (`pulsar-edit/pulsar`): живой форк,
версия 1.132.1, Electron 30, есть сборки под Apple Silicon. Годится как
готовое решение, если нужно «просто работать сегодня».

### Волна 2 — Вес: измерения (`f6bea95`)

Измерено, а не оценено. Полностью в `docs/WEIGHT-RU.md`.

**Главное открытие:** пакет `github` весил 7.85 МБ исходников (32% от всех
пакетов) и тянул **56 МБ `node_modules` — 193 пакета** (React 16, Relay,
GraphQL, Babel 7, keytar), плюс git-бинарь `dugite` (~40 МБ).
Итого с его удалением ушло **≈105 МБ распакованного**.

**Честный вывод:** языковые пакеты, которые казались главным кандидатом на
удаление, весят всего 3.3 МБ. Диета по ним даст мало. Основной вес — Electron.

**Про орфографию (вопрос владельца):** `spell-check` использует
`ALWAYS_USE_SYSTEM` → нативный `NSSpellChecker` macOS. Работает со словарями
системы, **сети ноль**. Оставляем.

### Волна 3 — Apple Silicon (✅ `f126e14`)

Была самая тяжёлая волна: родного пути для arm64 у Atom не существовало.

**Что мешало (всё найдено и починено):**

| Проблема | Причина | Решение |
|---|---|---|
| Node 12 не существует для arm64 | сборка Atom написана под Node 12.16.3 | Rosetta 2: Node 12 запускается как x64-процесс, а цель сборки задаётся отдельно (`ATOM_ARCH`) |
| apm для macOS жёстко требовал x64 | `getElectronArch()` возвращал `'x64'` для darwin во всех версиях | патч в `script/lib/install-apm.js` — ветка darwin уважает `ATOM_ARCH` |
| Нативные модули выходили интеловскими | gyp-генератор `make` не передаёт компилятору `-arch` вообще | `addTargetArchFlags()` в `script/lib/run-apm-install.js` |
| Бинарники получались «универсальными» | clang добавлял срез под процесс-родителя | `script/lib/thin-native-modules.js` — `lipo -thin arm64` |
| superstring не собирался | Xcode 16 поменял тип `iconv_t` | заголовок `script/macos-iconv-compat.h` + Xcode 16.2 |
| git-utils не собирался на Xcode 16.3+ | Apple начала определять `TARGET_OS_MAC`, старый zlib подменяет `fdopen` | зафиксирован Xcode 16.2 |
| mksnapshot падал на `gen/v8/embedded.S` | упаковщик не создаёт каталог | каталог `gen/v8` + повтор с `--embedded_src=/dev/null` |
| Дамп символов ронял сборку | `minidump` не умеет бинарники с двумя архитектурами | дамп выключен: краш-репортов в форке нет |

**Результат:** приложение собирается полностью, бинарник arm64, нативных
модулей не под arm64 — ноль.

### Волна 3.5 — правила CI и встроенный apm (`4c5bd98`)

**Правила сборки переделаны по решению владельца:** сборка под Intel удалена
целиком (она была страховкой на время переезда), осталась одна задача —
macOS arm64, на push и по кнопке. Временная диагностика архитектур больше не
запускается на push.

**Встроенный менеджер пакетов `apm` убран из приложения.** Он был
единственным крупным компонентом, который не мог стать нативным: apm
запускается собственным Node 12, поэтому в бандле лежал второй бинарник Node
(36 МБ, x64) и 67 МБ зависимостей, из которых 33 МБ — свой npm 6. Работало это
только через Rosetta и только ради загрузки пакетов из сети.

| | Было | Стало |
|---|---|---|
| Приложение | 598 МБ | **495 МБ** |
| Архив | 178.5 МБ | **160.2 МБ** |
| Компоненты не под arm64 | 3 | **0** |

Сам apm остался инструментом сборки: он по-прежнему ставит зависимости
приложения в `script/bootstrap`. Пакеты в редактор кладут файлами
(`~/.atom/packages`) или включают в сборку.

**Как читать цифры сборки, если что-то нужно посмотреть:** шаг «Вес по частям»
печатает вес частей приложения, а слово `[logs]` в сообщении коммита просит CI
сохранить отчёт (в том числе `weight.txt`) в `.ci-logs`. По галочке при ручном
запуске — то же самое. Артефакты GitHub из песочницы не скачиваются.

| `mocha`, `chai`, `sinon`, `jasmine-*`, `yargs-unparser`, `mock-spawn` | 19 МБ | нужны только спецификациям; во второй части диеты убраны из зависимостей совсем |

| `winreg`, `fswin`, `winattr` | 0.6 МБ | существуют только для Windows |

**Измерено:** приложение 493.7 → **429.1 МБ**, архив 160.2 → **144.8 МБ**,
`app.asar` 272.5 → **208.2 МБ**. Официальный Atom — 203 МБ архивом.

### Волна 5, вторая часть — диета 2.0: тесты и отладка убраны из зависимостей

Решение владельца: тестовые библиотеки не нужны вовсе (вариант «убрать совсем»).

| Что сделано | Почему |
|---|---|
| `mocha`, `chai`, `sinon`, `jasmine-*`, `mocha-*-reporter`, `mock-spawn` — убраны из `package.json` | нужны только спецификациям Atom |
| `dalek` (встроенный пакет) убран вместе с `require` в генераторе снапшота | прогонщик тестов пакетов |
| `devtron`, `chart.js` — убраны | отладка и графики; ни одного `require` в коде |
| `script/prune-lock-orphans.js` — чистка замка | убрано 311 записей, включая `dugite` (целый git от пакета `github`) |
| `moment` возвращён в сборку | его читает пакет `notifications`: раньше он был исключён ошибочно |
| Шаг сборки «Диета — состав приложения» | проверяет состав, а не вес; отчёт `.ci-logs/packages.txt` |

**Измерено локально** (npm 6, как в apm): установка **690 пакетов / 233 МБ**
вместо 846 / 305 МБ — минус 72 МБ ещё до упаковки.

**Измерено в сборке** (прогон 38657484428 ✅): приложение **429.2 МБ**,
`app.asar` 208.4 МБ, архив **144.0 МБ**; состав проверен — убранного нет,
нужное (включая `moment`) на месте; дерево зависимостей приложения — 502 пакета
/ 244.7 МБ. Архив почти не изменился: убранное и раньше не клалось в
приложение, а `moment` вернулся. Подробный разбор и полный список тяжёлых
пакетов — в `docs/WEIGHT-RU.md`.

⚠️ Тесты Atom теперь не запускаются (`script/test`): библиотеки придётся
поставить обратно — команда записана в `package.json` в комментарии `// ATOM LITE`.

**Грамматики и emoji — решено НЕ трогать.** Владелец: языковые грамматики
`tree-sitter` (≈ 65 МБ) остаются все, `emoji-images` (10.7 МБ) — решить позже.
Свободный вариант на будущее: `typescript` (30 МБ) нужен только для запуска
пакетов, написанных на TypeScript, — при желании это ещё треть app.asar.

### Волна 4 — темы `dajet` и `joer`

Сделаны четыре пакета: две пары «интерфейс + подсветка» (см. таблицу в
`docs/THEMES-RU.md`). Пара `dajet` включена по умолчанию (`core.themes`),
`joer` выбирается в настройках вместе с пятью атмосферами.

* цвета сняты с источников по числам: палитра и метрики плеера, токены сайта
  joer.ru (пять атмосфер);
* сборка с темами: 429.3 МБ распакованного, `app.asar` 208.5 МБ, архив
  144.3 МБ (прогон 38634160520) — темы добавили к `app.asar` около 0.3 МБ;
* настройки темы живут в Settings → Themes (штатный `configSchema`, как
  у `one-dark-ui`); `lib/main.js` ставит признак облика атрибутом на `<html>`,
  «как в системе» работает через `prefers-color-scheme` — без обработчиков;
* договор с чужими пакетами выполнен полностью: объявлены все 56 имён
  интерфейса и 30 имён подсветки из базового набора Atom, потому что 184 места
  в пакетах считают из них оттенки;
* проверка — `node script/check-themes.js` (компиляция LESS 2.7, пробный
  «чужой пакет», базовый набор, висячие переменные CSS) и тем же шагом в
  сборке — перед долгой сборкой, чтобы ошибка темы не стоила часа;
* посмотреть глазами без сборки — `node script/preview-themes.js`: собирает
  `theme-preview.html`, макет окна с настоящими классами Atom и
  переключателями облика, атмосферы и подсветки;
* на этой проверке найдено и починено семь дефектов — список в
  `docs/THEMES-RU.md`, раздел «Что нашла проверка».

## Что нужно знать перед следующей волной

### Как теперь собирается проект

Коммит в ветку — и сборка идёт сама: **один джоб, macOS arm64**, ~35–40 минут
(при наличии кэша Electron/bootstrap). Чтобы пропустить сборку на документарных
правках, добавляй `[skip ci]` в сообщение коммита. Готовый архив лежит в
артефакте `atom-macos-arm64`, отчёт — в `atom-macos-report`, а при падении или
по слову `[logs]` в коммите — в `.ci-logs/`.

### Подсказка для локальных скриптов в песочнице Linux

Скрипты `node script/check-themes.js` и `node script/preview-themes.js` требуют
модуль `less@2.7.3`. Если в свежей песочнице нет `node_modules`:

```bash
npm install --prefix /tmp/tools less@2.7.3 js-yaml@3 prettier@1.19.1
ln -sfn /tmp/tools/node_modules node_modules
node script/check-themes.js
node script/preview-themes.js
rm -f node_modules   # обязательно убрать симлинк перед git commit!
```

### Что может пригодиться при следующей сборке

| Файл | Зачем |
|---|---|
| `script/lib/thin-native-modules.js` | ужимает `.node` до целевой архитектуры |
| `script/lib/run-apm-install.js` | добавляет `-arch` в CFLAGS при кросс-сборке |
| `script/lib/install-apm.js` | патчит apm, чтобы darwin-ветка уважала `ATOM_ARCH` |
| `script/lib/prepare-ripgrep.js` | кладёт ripgrep в кэш (vscode-ripgrep не умеет arm64) |
| `script/lib/include-path-in-packaged-app.js` | фильтр упаковки `app.asar` |
| `script/prune-lock-orphans.js` | чистка осиротевших записей в `package-lock.json` |
| `script/check-themes.js` | быстрая проверка компиляции и контракта тем (LESS 2.7) |
| `script/preview-themes.js` | генератор интерактивного превью `theme-preview.html` |
| `.github/workflows/diagnose-native.yml` | проба архитектур, запускается вручную |

### Тёмная сторона: старый Electron на новой macOS

Electron 11 = Chromium 87 (ноябрь 2020). На macOS 26 поведение проверяется
на живом Mac владельца. Если приложение не запускается или глючит интерфейсом,
вероятная причина именно в старом Electron — тогда отдельной большой волной
планируется апгрейд Electron.
