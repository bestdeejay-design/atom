# ADR-0003. Концепция тишины

**Статус:** Принято
**Дата:** 2026-10-15

## Контекст

Большинство редакторов шумят: всплывающие окна, уведомления, значки, «совет дня», баннеры обновлений, проактивные подсказки ИИ, звуки, анимации, телеметрия в фоне. Пользователь теряет фокус, а редактор становится собеседником, которого никто не звал.

Владелец задал направление: **концепция тишины**. Редактор говорит, только когда его спросили, и не требует внимания сам.

## Решение

Тишина — обязательное ограничение для всех фич. Фича, которая нарушает принцип, не попадает в релиз без отдельного ADR.

### Шесть правил

1. **Не перебивать.** Модальные окна — только при риске потери данных (несохранённые изменения при закрытии). Рутинные события (сохранение, форматирование, переключение ветки) не показывают окон и тостов. Ошибки видны там, где возникли: в строке, в гаттере, в статус-строке.
2. **Не звать назад.** Нет уведомлений macOS, значков на Dock, отскока иконки, звуков по умолчанию, экранов «оцените нас», туров, апсейлов. Нет баннеров о новой версии.
3. **Не шуметь в сети.** Ноль фоновых запросов (см. ADR-0005).
4. **Не решать за пользователя.** Нет проактивного ИИ: подсказки, правки и комментарии появляются только по явной команде. Автоформат при сохранении выключен по умолчанию. Ничего не устанавливается и не обновляется без действия пользователя.
5. **Визуальная тишина.** Минимум хрома: скрываемая боковая панель, статус-строка с 2–3 элементами, нейтральная палитра, один акцентный цвет. Анимации короче 150 мс и уважают «Уменьшить движение». Прозрачность и стекло (Liquid Glass) — только для плавающих элементов, не для текста.
6. **Предсказуемость.** Настройки — обычный текстовый файл и экран с теми же значениями. Никаких скрытых флагов. Всё, что меняет поведение, видно в настройках.

### Скорость как часть тишины

Если действие занимает меньше 100 мс, спиннера нет. Если дольше 1 с, показываем статус в строке, а не окно.

### Тишина и плагины

Плагины подчиняются тем же правилам. Плагин не может показать уведомление macOS, открыть модальное окно без действия пользователя или отправить сетевой запрос без разрешения (ADR-0004). Плагин, который нарушает тишину, отключается с записью в журнал.

## Альтернативы

- **Мягкая тишина (только рекомендация).** Отклонено: без жёстких правил фичи будут шуметь по одной.
- **Тишина как отдельный режим «Фокус».** Отклонено как единственный вариант: тишина должна быть по умолчанию, а не включаться вручную. Режим фокуса может существовать как дополнительный, но не заменяет принцип.

## Последствия

- Каждая фича в `docs/FEATURE-LIST-RU.md` получает пометку о том, как она соблюдает тишину.
- Нужны автоматические проверки: например, тест «при обычной работе не показывается ни одного модального окна» и тест «в простое ноль сетевых соединений».
- Онбординг короткий: одно окно с пустым проектом, без туров.

## Как проверить (тесты приёмки)

- Ручной сценарий «день работы» (открыть проект, править, сохранить, переключить ветку, закрыть): ноль модальных окон, ноль уведомлений.
- В простое 10 минут: ноль сетевых соединений, ноль записей фоновых задач в журнал (кроме сохранения автокопий).
- Мониторинг Dock и центра уведомлений: ни одного значка и ни одного уведомления.
- Все анимации проверяются при включённом «Уменьшить движение».
