# ADR-0004. Плагины: папки на диске, разрешения, стор — опционально

**Статус:** Принято (JavaScriptCore подтверждён владельцем, 2026-10-15). Публикация в стор — уровень 3 — остаётся опциональной и не входит в MVP.
**Дата:** 2026-10-15

## Контекст

Владелец хочет, чтобы каждый мог добавить свою функцию, а публиковать её в сторе — по желанию, или не публиковать вовсе: написал, поставил, пользуется.

Atom показал, что пакетная система с реестром, npm-зависимостями и доступом ко всему Node быстро превращается в проблему веса, безопасности и поддержки. Новая модель должна быть проще.

## Решение

### 1. Плагин — это папка

```
my-plugin/
  plugin.toml      # манифест
  main.js          # точка входа
  assets/          # необязательно
```

Минимальный манифест:

```toml
id = "local.word-count"
name = "Счётчик слов"
version = "0.1.0"
api = "1"                       # версия API редактора
entry = "main.js"
capabilities = ["commands", "text.read", "ui.status"]
```

Установка: скопировать папку в каталог плагинов (`~/Library/Application Support/<App>/Plugins/`) или выбрать «Установить из папки» в настройках. Перезапуск не нужен. Удаление — удалить папку.

### 2. Среда выполнения: JavaScriptCore

- Системный фреймворк macOS: **нулевой вес** в бандле, не нужен Node.
- Каждый плагин выполняется в отдельном `JSContext` на фоновой очереди.
- Редактор предоставляет только API, объявленный в `capabilities`. Всё остальное недоступно.
- Бесконечные циклы: плагину задан лимит времени на вызов; при превышении он останавливается и отключается с записью в журнал.

### 3. Разрешения по возможностям

| Capability | Что даёт |
|---|---|
| `commands` | Регистрация команд (попадают в палитру и меню) |
| `keymap` | Предлагать горячие клавиши (пользователь подтверждает) |
| `text.read` | Читать текст открытого документа |
| `text.edit` | Менять текст (только через транзакцию, с откатом) |
| `fs.project.read` | Читать файлы текущего проекта |
| `fs.project.write` | Писать в проект (с подтверждением при первом запуске) |
| `ui.status` | Элемент в статус-строке (не больше одного на плагин) |
| `ui.panel` | Боковая панель (скрытая по умолчанию) |
| `network` | Сетевые запросы. **Выключено по умолчанию**, требует явного разрешения пользователя для каждого домена |

Без `network` плагин не видит сети совсем. Без `fs.project.write` не может менять файлы.

### 4. Публикация: три уровня

1. **Только локально.** Папка на диске, никаких регистраций.
2. **Поделиться.** Папка или git-репозиторий, ссылка от автора, установка через «Установить из папки» или по URL (только по явному действию).
3. **Стор (позже, опционально).** Простой индекс: статический JSON-файл со списком плагинов, ссылками на репозитории и контрольными суммами. Без аккаунтов и сервера в MVP. Подписи авторов — необязательны, но поддерживаются.

Стор не входит в первую версию. Редактор работает полностью без него.

### 5. Версионирование API

- Поле `api` в манифесте. Редактор отказывается загружать плагин с несовместимой версией API и говорит об этом один раз, в журнале и в настройках плагинов (не всплывающим окном).
- Ломающие изменения API — только при смене major-версии, с переходным периодом.

## Альтернативы

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| **JavaScriptCore** | Системный, без веса, знакомый язык | Меньше изоляции, чем у WASM | **Выбран** |
| WebAssembly (wasmtime и т. п.) | Сильная изоляция, любой язык | Тяжёлый рантайм, сложнее для новичков | Пересмотреть, если JS окажется недостаточен |
| Swift-динамические библиотеки (`.dylib`) | Максимальная скорость, нативно | Нет песочницы, нужна подпись и Xcode у автора | Отклонено для пользовательских плагинов |
| Lua | Очень маленький рантайм | Бедная экосистема, отдельный язык для многих | Отклонено |
| Использовать Atom-пакеты | — | Node, CoffeeScript, мёртвый реестр | Отклонено (ADR-0001) |

## Последствия

- Нужен документ «Как написать плагин» и пример из 20 строк.
- Нужен режим разработки: перезагрузка плагина по сохранению файла (только в режиме разработки, не по умолчанию).
- Безопасность — честная: капабилити ограничивают API, но не являются полноценной изоляцией процесса. Об этом сказано в документации. Если понадобится строгая изоляция, пересматриваем вариант WASM.
- Любой плагин может стать публичным без изменений кода: публикация — это только место, где лежит папка.

## Как проверить

- Плагин без `network` при попытке сетевого запроса получает ошибку, и в сети нет соединения.
- Плагин с `text.edit` может откатить свою правку одной командой «Отменить».
- Плагин с бесконечным циклом останавливается за заданный лимит, редактор продолжает работать.
- Установка из папки работает без перезапуска.
