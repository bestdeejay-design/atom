# ADR-0001. Чистый лист: ничего не импортируем из Atom

**Статус:** Принято
**Дата:** 2026-10-15

## Контекст

В репозитории лежит форк Atom («Lite») с собственными доработками: палитры `dajet` и `joer`, keymap-файлы, схема настроек, список языков, иконка. Первый вариант плана предлагал переносить их в новый редактор. Владелец решил иначе: новый редактор пишется с нуля, а возможности определяются фич-листом, а не наследием.

## Решение

1. **Нет переноса кода.** Ни одна строка из `src/`, `packages/`, `script/`, `spec/` не попадает в новый проект.
2. **Нет переноса ассетов.** Иконки, палитры, шрифты, `Info.plist` и вообще любые файлы из `resources/` и `packages/*-ui`, `packages/*-syntax` не копируются. Визуальный язык создаётся заново по концепции тишины (ADR-0003).
3. **Нет переноса настроек и горячих клавиш.** Импорт `~/.atom/*.cson` не делаем. Пользователь начинает с чистого состояния.
4. **Нет переноса пакетов.** Atom-пакеты несовместимы с новой моделью плагинов (ADR-0004).
5. **Atom — источник идей, не источник кода.** Можно изучать поведение (например, как работает команда «переместить строку»), но реализация пишется заново. Если кусок Atom всё же понадобится (например, таблица Unicode-свойств), это отдельный ADR с указанием лицензии MIT и причины.
6. **Тренды — внешний ориентир.** Выбор технологий опирается на текущее состояние платформы (см. раздел «Тренды» в `docs/NATIVE-REWRITE-PLAN-RU.md`), а не на то, что уже есть в форке.

## Альтернативы

- **Перенос палитр и keymap.** Отклонено: тянет за собой Atom-модель (селекторы, scope-имена) и делает новый проект зависимым от старого.
- **Развитие форка Atom Lite.** Отклонено: Electron 11, CoffeeScript, мёртвый реестр пакетов. Лёгкость не достигается патчами.

## Последствия

- Все возможности начинаются с нуля и фиксируются в `docs/FEATURE-LIST-RU.md`.
- Текущие дизайн-решения `dajet` и `joer` **не используются** в новом проекте. Если владелец хочет сохранить их как «фирменный» стиль, это отменит пункт 2 и требует отдельного ADR.
- Лицензия: новый проект не обязан быть MIT, пока он не содержит кода Atom. Выбор лицензии — отдельное решение владельца.

## Как проверить

- Поиск по новому репозиторию: в дереве нет каталогов `src/`, `packages/`, `apm/`, `resources/mac/` из Atom.
- В `Info.plist`, иконках и названиях нет слов «Atom» или «dajet»/«joer», если владелец не решил иначе.
